# Что я сделал

Я написал Android-приложение, которое помогает рассчитать доход по вкладу со сложным процентом и ежемесячным пополнением. В приложении есть 5 экранов: главное меню, два шага ввода параметров, экран с результатом и экран истории всех расчётов.

## Как это работает внутри (простыми словами)

### 1. Внешний вид и навигация (Compose)

Всю графику я сделал на Jetpack Compose. Вместо того чтобы создавать кучу разных активити или фрагментов, я использовал библиотеку Navigation Compose (NavHost). У меня есть один главный файл MainActivity, в котором прописаны "маршруты" для каждого экрана (step1, step2, result и т.д.). Переходы работают плавно, а кнопка "Назад" возвращает куда надо.

### 2. Логика и данные (MVVM)

- Чтобы при повороте экрана введенные данные не пропадали, я использовал архитектуру MVVM. Я создал класс DepositViewModel. Это "мозг" приложения. В нём:

- Хранятся текущие цифры, которые пользователь ввел в текстовые поля (в объекте UiState).

- Написана формула расчёта вклада (капитализация с пополнением).

- Лежит логика доступных ставок (ставка сама понимает, что ей показать, исходя из введенных ранее месяцев). UI (кнопки и тексты) просто "наблюдает" за этим ViewModel и перерисовывается, если цифры меняются.

### 3. База данных (Room)

- Для сохранения истории расчётов я подключил библиотеку Room (это удобная обертка над SQLite):

- Таблица: Создал класс DepositEntity, который описывает колонки в таблице (взнос, срок, итог).

- Запросы: В интерфейсе DepositDao написал SQL-команду для сохранения и выборки всех записей.

- Выборка истории работает через Flow - это значит, что когда я сохраняю новый расчёт, список на экране истории обновляется автоматически, без дополнительных запросов.

- Саму базу я сделал Синглтоном (чтобы она висела в памяти в единственном экземпляре и не тормозила телефон), а запросы к ней спрятал за Репозиторием - так код выглядит чище.

### 4. "Защита от дурака" (Валидация)

Я заморочился с текстовыми полями, чтобы приложение нельзя было сломать:

- Ввести буквы или минусы не выйдет - они сразу фильтруются.

- Запятые автоматически меняются на точки для дробных чисел.

- Если попытаться ввести "05" месяцев или "0500" рублей - первый ноль автоматически сотрется. Приложение не даст ввести 0 как стартовый взнос или срок.

- Кнопка "Далее" тупо не нажмется, пока поля пустые или равны нулю.


Итог: Приложение работает стабильно, не падает при поворотах экрана, корректно считает сложные проценты и хранит историю в локальной БД телефона.
