# Что я сделал

Я написал Android-приложение, которое работает как простой счетчик. В нем отображается текущее значение, есть три кнопки (Плюс, Минус, Сброс), а также показывается история последних 5 действий.

## Как это работает внутри (простыми словами)

### 1. Внешний вид (Compose)

Весь интерфейс я сделал на Jetpack Compose. У меня есть один экран CounterScreen, на котором расположены текстовые поля, кнопки и список для истории (сделан через LazyColumn, чтобы список работал быстро). Каждая кнопка на экране просто вызывает нужный метод из ViewModel.

### 2. Логика и данные (MVVM и UiState)

- Чтобы счетчик не сбрасывался в ноль при каждом повороте экрана телефона, я использовал архитектуру MVVM. Я создал класс CounterViewModel. Это - "мозг" моего счетчика. В нем:

- Хранятся текущие данные - само число и список истории. Я объединил их в один объект CounterUiState.

- Написана логика для кнопок - как именно увеличивать число, уменьшать его и как обновлять список, чтобы там всегда оставалось только 5 последних действий (использовал функцию take(4) и добавлял новое действие в начало).

- Само состояние я храню в StateFlow. Это специальный поток данных, за которым интерфейс умеет "наблюдать". Как только я меняю значение во ViewModel, экран автоматически перерисовывается с новыми цифрами.

### 3. Правильная архитектура

Я строго разделил код - интерфейс ничего не знает о том, как считать цифры, а ViewModel ничего не знает про то, как выглядят кнопки. Экран только отправляет команды (например, "нажали плюс") и рисует то состояние, которое ему отдает ViewModel.


Итог: Приложение работает отлично, история правильно отсекается до 5 элементов, а состояние счетчика надежно сохраняется при любых переворотах экрана. Архитектура MVVM соблюдена полностью.
